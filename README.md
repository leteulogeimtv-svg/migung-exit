# 미궁의 출구 (Exit of the Labyrinth)

> 바이브 코딩으로 만든 **16비트 풍 1인칭 3D 미로 탈출 게임**. 30개 층의 미궁을 돌파하고 최종 보스 드래곤을 쓰러뜨리면 엔딩 크레딧이 나옵니다.
> 파일 하나(`index.html`)로 동작하며, 브라우저에서 바로 실행됩니다.

- **실행 방법**: `index.html`을 브라우저(Chrome 권장)로 열기 / GitHub Pages: `https://<아이디>.github.io/<저장소>/`  ← (배포 후 주소로 교체)
- **조작**: WASD 이동 · 마우스 시점 · 좌클릭 공격 · 우클릭 줍기 · 마우스 휠 → 무기 선택판(Z/X, X로 장착) · R 재장전 · 숫자키 1~0, F1~F8 아이템 선택 · 스페이스 사용 · Esc 일시정지 · M 소리
- **기술**: HTML / CSS / JavaScript (외부 라이브러리 없음), 캔버스 소프트웨어 레이캐스터(320×200), Web Audio 실시간 합성 효과음·BGM

## 1. 제작한 것 소개

### 한 줄 소개
무작위로 생성되는 미로에서 몬스터를 쓰러뜨려 열쇠를 얻고, 출구를 열어 다음 층으로 내려가는 로그라이크풍 1인칭 액션 게임입니다.

### 실습 과제 시점 → 중간고사 제출 시점 비교

> ⚠️ 실습 과제 때 제출한 버전의 실제 내용에 맞게 왼쪽 열을 수정하세요. (아래는 이 프로젝트의 초기 버전 기준입니다.)

| 항목 | 실습 과제 시점 | 중간고사 시점 (현재) |
|---|---|---|
| 규모 | 5층 | **30층**, 층마다 다른 배경 무늬·색·장식, 층마다 다른 보스 |
| 그래픽 | 기본 3D 미로 | **16비트 도트 풍** 스프라이트·벽 텍스처 |
| 로그인 | 외부 계정 로그인 | **닉네임 + 나이** 입력 로그인 (미로그인 시 플레이 불가) |
| 소리 | 없음 | 몬스터 소리·검 휘두르기·처치·아이템 획득 효과음, 층별 BGM, 엔딩 크레딧 BGM (모두 Web Audio 합성) |
| 아이템 | 포션 등 소수 | **18종** (포션, 엘릭서, 폭탄, 서리, 가속, 수호 부적, 흡혈 등), 스페이스 사용 + 숫자키/F키 선택 |
| 무기 | 검 1종 | **6종**: 검, 엽총, 활, 머신건, 수류탄, 방패 + 원형 무기 선택판(마우스 휠, Z/X) |
| 몬스터 | 정지 상태로 접근 | 종류별 **공격 모션**(예비 동작 → 타격), 시야 확인 후 공격 |
| 위험 요소 | 체력 감소 | 좀비꽃 **물어뜯기 연출 + 감염(화면 침식)**, 완전 감염 시 좀비화 게임 오버 |
| 게임 오버 | 단순 문구 | **스프라이트 애니메이션 데스씬**: 용사가 몬스터에게 직접 당하는 장면(공격 → 타격 정지 → 쓰러짐), 몬스터 종류별 연출, **30개 층 보스마다 전용 데스씬**(삼켜짐·참수·동상화·두 동강·화염 등) |
| 저장 | 없음 | 층 입장 시 **자동 저장 / 이어하기** |
| 최종 | 없음 | 드래곤 최종 보스, **엔딩 크레딧** |
| 배포 | 웹 | 웹 + 모바일 터치 조작(가상 방향키·공격·줍기), Android/iOS(Capacitor), Windows exe(Neutralino) |

### 주요 기능
1. **레이캐스팅 3D 미로** – 재귀 백트래킹으로 층마다 새 미로 생성, 거리 안개와 디더링으로 16비트 분위기 연출
2. **전투 시스템** – 무기 6종(근접·연사·범위·방어), 탄약·재장전, 몬스터 처치 시 탄약/아이템 드롭
3. **30층 진행** – 층이 올라갈수록 몬스터 체력·공격력·수가 증가, 5층마다 구역(테마) 전환
4. **좀비꽃 감염** – 물리면 연타로 뿌리치는 미니 연출, 감염도가 오르면 덩굴 모양 침식 화면, 아이템으로 치료
5. **데스씬 시스템** – 관절 포즈로 움직이는 용사 스프라이트를 24프레임 단위로 그려 몬스터에게 당하는 과정을 보여줌. 일반 몬스터는 계열별(슬라임·골렘·박쥐·뱀·꽃·유령·마법사·용), 보스 30종은 각자 전용 장면. 클릭/스페이스로 건너뛰기
6. **닉네임 로그인 + 기록** – 이 기기 최고 기록 저장(공유 랭킹은 Claude 아티팩트 환경에서만 동작, 실패해도 게임은 정상)

## 2. PRD와 Todo 리스트

### PRD (Product Requirements Document)

**목적**: 코드를 직접 짜지 않고 AI에게 요구사항을 말로 전달하는 바이브 코딩만으로, 설치 없이 브라우저에서 즐길 수 있는 완성도 있는 게임을 만든다.

**대상 사용자**: 가볍게 즐길 수 있는 액션 게임을 찾는 학생·일반 사용자 (PC 브라우저 우선, 모바일 보조)

# 작업 절차
1. 기능을 Todo로 쪼갠 뒤 하나씩 구현한다.
2. 구현마다 Playwright로 실행해 스크린샷과 콘솔 에러를 확인한다.
3. 상태는 전역 객체(G)에 모으고, 새 기능은 기존 update/render 루프에 연결한다.
4. 소리는 Web Audio 합성만 사용한다(외부 파일 금지).
5. 저장소(localStorage) 접근은 항상 try/catch로 감싼다.
6. 한 Todo가 끝나면 "무엇을 했는지" 한 줄 커밋 메시지로 커밋한다.

# 점검 목록

- 모바일 터치 입력이 깨지지 않는가
- 새 기능이 세이브/이어하기와 충돌하지 않는가

## 5. 느낀점, 결론

### 느낀점
- **말로 정확히 요구하는 능력이 곧 개발 실력이다.** "몬스터가 공격한다"보다 "공격 전에 예비 동작이 있고, 시야가 있을 때만 맞는다"처럼 구체적으로 말할수록 결과가 좋았다.
- **작게 나눠 요청하고 매번 실행해 보는 것이 중요하다.** 한 번에 큰 기능을 요청했을 때보다 Todo 단위로 확인할 때 버그(벽 너머 공격, 안드로이드 화면 문제)를 훨씬 일찍 찾았다.
- **AI가 만든 결과도 검증이 필요하다.** 스크린샷과 실제 기기 테스트에서 AI가 놓친 문제가 계속 나왔다. 테스트 후 수정 사항이 곧 이 프로젝트의 학습 내용이었다.
- **요구사항은 계속 변한다.** 5층 게임이 30층, 무기 6종, 감염 시스템까지 커졌다. PRD와 Todo를 갱신하며 관리하지 않았다면 범위가 걷잡을 수 없었을 것이다.

### 아쉬운 점
- 새 무기를 반영한 자동 밸런스 시뮬레이션과 터치 모드 재점검을 못 했다.
- 코드가 단일 파일로 커져 유지보수가 어렵다. 이후에는 모듈로 나누고 싶다.

### 결론
바이브 코딩으로 5층짜리 프로토타입에서 시작해 30층, 무기 6종, 감염·데스씬까지 갖춘 브라우저 게임을 완성했다. 개발자의 역할은 직접 타이핑하는 것에서 **요구를 정의하고, 쪼개고, 검증하는 것**으로 옮겨간다는 점을 체감했다.
